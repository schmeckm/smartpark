URS – Software zur Echtzeitberechnung von Queue Time, Throughput und Ride Efficiency für Freizeitparks
1. Zweck des Systems

Das System soll Echtzeitdaten aus Fahrgeschäften, Attraktionen, Restaurants und weiteren operativen Bereichen eines Freizeitparks erfassen, verarbeiten und analysieren. Ziel ist die Berechnung von:

Queue Time (Wartezeit)
Throughput (Personendurchsatz)
Ride Efficiency analog zum OEE-Modell in der Industrie
Kapazitätsauslastung
Verfügbarkeiten
Performance-Indikatoren
Prognosen mittels Machine Learning

Die Datenbasis bilden Maschinen- und Betriebsdaten, die über MQTT gemäß Sparkplug B auf einem Unified Namespace (UNS) in Echtzeit bereitgestellt werden.

2. Business Zielsetzung

Das System soll dem Betreiber ermöglichen:

Reduzierung von Wartezeiten
Optimierung des Personaleinsatzes
Höherer Gästezufriedenheit
Maximierung des Tagesdurchsatzes
Transparenz über Engpässe
Datengetriebene Steuerung des Parks
Predictive Operations

5. Funktionale Anforderungen (URS)
URS-001 Echtzeitdaten Empfang

Das System muss MQTT Nachrichten in Echtzeit empfangen können.

URS-002 Sparkplug B Unterstützung

Das System muss Sparkplug B Topics und Payloads interpretieren können.

URS-003 Unified Namespace

Das System muss Daten logisch im UNS strukturieren.

URS-004 Stammdatenverwaltung

Das System muss folgende Stammdaten verwalten:

Attraktionsname
Ride Type
Max Plätze
Zykluszeit Soll
Anzahl Züge
Öffnungszeiten
Restaurant Sitzplätze
Standort
URS-005 Ride Efficiency Berechnung (OEE ähnlich)

Für Fahrgeschäfte muss berechnet werden:

Availability

Zeit verfügbar / Betriebszeit

Performance

Tatsächliche Zyklen / Soll-Zyklen

Quality

Besetzte Plätze / maximale Plätze

Gesamt Ride Efficiency
Availability x Performance x Occupancy

Das System muss Wartezeiten berechnen basierend auf:

Warteschlangenlänge
Gästezufluss
Zykluszeit
Plätze pro Zyklus
