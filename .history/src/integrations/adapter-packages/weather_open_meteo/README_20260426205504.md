# Open-Meteo Weather (`weather_open_meteo`)

Park-level weather polling via [Open-Meteo](https://open-meteo.com/) (no API key). Produces normalized adapter observations with `domain: weather` and `assetSlug: current` for UNS topics and downstream ML feature pipelines.

## Configuration (`configSchema`)

| Field        | Required | Description                          |
| ------------ | -------- | ------------------------------------ |
| `sparkSlug`   | yes      | UNS park segment (e.g. `europapark`) |
| `latitude`   | yes      | Park centroid latitude               |
| `longitude`  | yes      | Park centroid longitude              |
| `timezone`   | no       | IANA zone for Open-Meteo (default `Europe/Berlin`) |

Coordinates should match the park entity from ThemeParks.wiki (`location.latitude` / `location.longitude`) — **one station per park**, not per ride.

## Outputs

- **Observations**: `WEATHER_OBSERVED` with metrics `temperature`, `rain_probability`, `rain_mm`, `wind_speed`, `weather_condition`.
- **Preferred outputProfiles**: `["SPARKPLUG_JSON", "CANONICAL_HISTORIAN"]` for MQTT Sparkplug + historian pipeline.
- **UNS JSON** (with `context.parkSlug`): `tpuns/{parkSlug}/v1/weather/current/{metric}`.
- **Sparkplug JSON** (with context below): topic `spBv1.0/europa_park/DDATA/weather_gateway/current`.

Recommended weather context example:

```json
{
  "sparkSlug": "europapark",
  "sparkplugGroupId": "europa_park",
  "sparkplugEdgeNode": "weather_gateway"
}
```

Use `SPARKPLUG_JSON` for MQTT Sparkplug output. Use `UNS_JSON` only for human-readable TPUNS topics.

Weather is **not** attached to queue-time or ride events; ingest latest park-level state and **join at ML snapshot** time.

## Runtime

Loaded automatically from `src/integrations/adapter-packages/weather_open_meteo` by `AdapterPackageLoaderService`.

Install-time settings (`configJson`, `contextJson`, `outputProfiles`, `emitEnabled`, …) are stored by the **adapter framework** in a per-adapter YAML file under `data/adapter-install-config/` (same for every adapter package), not inside `metadata.install` in the database.

Poll via API or smoke:

```bash
npm run smoke:weather-adapter
```

Or `AdapterRuntimeService.runLocal({ adapterKey: 'weather_open_meteo', mode: 'poll', config, context, profiles: ['SPARKPLUG_JSON', 'CANONICAL_HISTORIAN'], emit: false })`.

## Permissions

`network: true` (HTTPS to `api.open-meteo.com`).
